## Context

`llm` 0.8.0 (tag object 73ba920b on commit 7873aa63, released 2026-10-20) closes gaps
`story:llm-over-b10x-llm` worked around: `Capabilities` declares `output_streaming` and
`input_during_output`; every `StreamEvent` is documented final and a successful turn's text is the
shown deltas; a call rejected before running is sent as `failed: true` with the reason as the
caller's text in `output`; provider failures before output are retried by the `llm` clients.
Approved on 2026-10-20 under the owner's standing exception for ADR work, relayed by session
adr-changes.

## Planned scope

- `inference-llm` pins `b10x-llm-core` at tag 0.8.0. `Capabilities` struct literals use
  `..Capabilities::text(..)` (testkit `src/llm.rs:233`, inference-llm tests `model_turns.rs:67`,
  `adversary1_turn_sequencing.rs:75`).
- The wrapper reads `output_streaming` and `input_during_output`: a `Generator` refuses an Adapter
  claim its model does not declare (`OutputStreaming` without `output_streaming`,
  `ConcurrentInputOutput` without `input_during_output`), and a model that does not stream gets
  one segment per turn from `llm`'s declaration.
- The "`llm` does not state it" notes on delta finality go (`crates/inference-llm/src/lib.rs:30`,
  `docs/design/inference.md:371`); they cite `llm`'s rule.
- A rejected call's reason is the caller's text in `output`, `failed: true`, per `llm`'s
  convention; the graph keeps ToolCallFailed and ToolCallRejected apart.
- A doc line: retries before output are the `llm` client's; a failing turn still cancels the
  generation.
- Kept: input admitted during output becomes the next turn's text (no protocol carries input
  during output); the git-tag pin (llm crates are `publish = false`).
- Before merge: every Adapter record the new refusal hits, with file:line.

## Acceptance

The workspace builds on `llm` 0.8.0 with the same conform counts; an Adapter claim its model does
not declare is refused with a test; the gap notes are gone; the list of Adapter records the
refusal hits is reported.
