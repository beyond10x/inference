## Context

A downstream adopter runs its text calls through `llm` 0.20.0 (2026-10-30) and its voice and
realtime calls through this repository, which pins `llm` 0.8.3. The two pins put two copies of
`llm-core` in its tree, so the two cannot share one provider stack. Moving the pin to 0.20.0 is
the fix.

What changed in `llm` between 0.8.3 and 0.20.0 that reaches this repository:

- 0.10.0 drops the `b10x-` prefix from every package (`b10x-llm-core` is `llm-core`); library
  names are unchanged.
- New variants of exhaustive enums: `Item::AssistantRefusal` and `StreamEvent::RefusalDelta`
  (0.20.0), `Protocol::BedrockConverse` (0.11.0), `Advisory::AnthropicBeta` (0.13.0).
- New public fields: `Error::refusal` (0.18.0), `Controls::return_unpublished_calls` (0.17.0),
  `Hints::anthropic_beta` (0.13.0).
- `llm-chat` reads a Chat Completions `refusal` as refusal text, never as assistant text (0.20.0).

## Planned scope

- Every `llm` dependency moves from tag 0.8.3 to 0.20.0: the workspace `llm-core` and `llm-cost`
  and the llama-server adapter's `llm-blocking`, `llm-chat`, `llm-credentials` and `llm-http`,
  without the `package =` rename; `Cargo.lock` for the `llm` packages only.
- `llm_release` reads `llm-*` packages at 0.20.0.
- Refusal text is not generation text: `inference-llm` reads only `StreamEvent::TextDelta` and
  `Item::AssistantText`, so a refusal adds no segment (owner decision, 2026-11-04).
- `AGENTS.md`'s rule on the `llm` repository names 0.20.0.
- Release 0.12.0, breaking: `llm_core` types in the public API are now 0.20.0's.

## Domain relations

## Acceptance

`cargo tree -p inference-llama-server --all-features --locked` lists every `llm-*` package at
0.20.0 and no `b10x-llm-*` package; `llm_release` pins it. The tests of `inference-llm`,
`inference-llama-server` and `inference-facade` (feature `cost`) pass offline, and `task check`
passes.
