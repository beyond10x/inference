## Design

`docs/design/sdk.md` (draft, 2026-10-21, revised 2026-10-22 after the plan critics) is the design;
this record holds its decisions and open questions so the plan can point at them.

## Decisions in the draft

| id | decision | section |
|---|---|---|
| D1 | the SDK is the `inference` crate the design reserves (`docs/design/inference.md:245`) | §0 |
| D2 | five layers, each using only the one beneath: one call, handles, recipes, graph, contracts | §3 |
| D3 | `inference::Payload` lives in the `inference` crate (`crates/inference/src/payload.rs`) and implements every payload trait of the workspace, `SessionPayload` and `PlaybackPayload` included; `inference-pipeline` keeps only the per-modality default port traits, because the facade depends on the pipeline and a payload there could not implement `SessionPayload` | §3.4 |
| D4 | the stack (`inference.sdk.Stack`) is the only configuration noun; resolution order builder, environment, `INFERENCE_STACK`, `./inference.toml`, user config | §4 |
| D5 | a stack never crosses a profile boundary and never falls back to another adapter | §4.3 |
| D6 | the SDK chooses Tokio; the contracts stay runtime-neutral | §8 |
| D7 | `Agent::close` delivers every event received before it, then `Event::Closed` | §3.2 |
| D8 | adapter registrations live in `crates/inference/src/registry/`, one file per adapter feature, never in the adapter crates, which `inference` depends on | §4.4 |

| D11 | the agent's time comes from an `inference::Clock`; `inference::testing::FakeClock` implements it | §3.2, §6 |
| D12 | `inference::sessions()` (the process-wide `LiveSessions` every SDK session opens on, defined by story:sdk-agent) and the `_with` forms of D18 are public; `speak_with(&stack, text, host)` and `talk_with(&stack, host)` sit behind `audio-host` (an `AudioHost`, no cpal), and `speak` and `talk`, which open the default `CpalHost`, behind `audio-device`, which implies `audio-host`; `testing` implies `audio-host` and not `audio-device` | §3.1 |
| D13 | each macro (`tool`, `main`) emits only `::inference::…` paths: `::inference::tools::…`, `::inference::__private::{serde, schemars, serde_json, tokio, exit}`, `::inference::audio_device::CpalHost`, `::inference::Stack` and `::inference::Result`; the generated arguments struct carries `#[serde(crate = "::inference::__private::serde")]` and `#[schemars(crate = "::inference::__private::schemars")]`; `lib.rs` declares `extern crate self as inference;` so the paths resolve inside the crate too. | D14 | the testkit takes `inference` only as a dev-dependency (the precedent: the testkit depends on `inference-facade` optionally, `crates/inference-testkit/Cargo.toml:12`, and the facade dev-depends on the testkit, `crates/inference-facade/Cargo.toml:24-31`); a test that uses both lives under `crates/inference-testkit/tests/` | §6 |
| D15 | the testkit mocks are registered under the adapter name `mock` in `crates/inference/src/registry/mock.rs`, behind `testing`, by story:sdk-stack | §4.4, §6 |
| D16 | `#[inference::main] async fn main(host: impl AudioHost, stack: Stack)`, with no return type, emits `pub async fn run(host, stack) -> inference::Result<()>` (the body with `Ok(())` appended under `#[allow(unreachable_code)]`, the seam tests call) and `fn main() -> ExitCode`, which starts a multi-thread Tokio runtime, calls `run` with `CpalHost` and `Stack::from_env()`, and returns `inference::__private::exit(result)` (`error: {e}` and its `source()` chain through `Display`). Multi-thread because a hosted adapter may block its calling thread while it connects: the AWS binding waits on a channel for its own pool (`adapters/inference-aws/src/duplex.rs:169-190`). The §3.2 program ends `println!("{}", agent.usage())`; `Usage: Display` never fails (`cost: unknown (no prices)` without a price document). T1 counts the whole example file, attribute and tool function included: 15 counted lines, 7 without the tool | §2, §3.2, §7, §8 |
| D17 | every builder binding goes through `Stack::bind(Binding)`, which takes no role because each binding carries its own: `Binding::named(Role, adapter, keys)` or a typed instance built by `Binding::stt`, `llm`, `tts` or `speech` (each a `Bound<role::X>`, D25), `bind` taking `impl Into<Binding>`, recorded as `BindingSource::Builder`; `Binding::model(self, name)` sets the role key `model` (`INFERENCE_<ROLE>_MODEL`), the serving model name prices are looked up by, which defaults to the provider model string where the adapter has one; `Stack::new()` is an empty stack, and `stack.resolve_with(&Env)` reads every other source from that `Env` and fills only the roles still unbound, so the order is builder, environment, `INFERENCE_STACK`, `./inference.toml`, user config; `Stack::from_env()` is `Stack::new().resolve_with(&Env::process())`; tests inject an `Env` and never touch the process environment | §4.2 |
| D18 | the `_with` form of an SDK call or handle constructor takes what the plain form defaults, in one order: the stack (`&Stack`) first, then the plain form's arguments, then the `AudioHost` where the plain form uses the default one: `transcribe_with(&stack, path)`, `chat_with(&stack, prompt)`, `speak_with(&stack, text, host)`, `talk_with(&stack, host)`, `Chat::new_with(&stack)`, `Transcriber::new_with(&stack)`, `Voice::new_with(&stack)`, as `Agent::voice_with(stack)` and `run_on_devices_with(host)` already are. A `_with` form uses the stack as given and resolves nothing more; the plain form is it over `Stack::from_env()` (and the default host). Tests bind the testkit mocks with `Stack::new().bind(Binding::<role>(<mock>))` and call the `_with` form | §3.1, §3.2 |
| D19 | `Agent`'s methods take `&self` except `switch`; it holds its session in one `Arc<Inner>` with no lock, because story:sdk-agent changes the facade so `LiveSession::receive` and `close` take `&self` (receive state behind a `std::sync::Mutex`, the ingress list cloned out before any await; `crates/inference-facade/src/live.rs:881-898`, `:967`) while `switch` keeps `&mut self`, as it reassigns the session's fields (`crates/inference-facade/src/switch.rs:77`, `:120-129`); one pump task owns `receive` (one waker slot, `live.rs:431-435`) and fans events out, so a handle shared through `Arc` can `send_audio` or `close` during `run_on_devices`; what the pump, a spawned close and `Drop` share is one `Arc<Inner>` (the session, the lifecycle state `Open`, `Switching`, `Closing`, `Closed` moved by compare-and-swap, the `AuthorityHandle` and the announced confirmations, and an `Arc<Route>` holding the sink slot and the event `Sender`, which the recipe also holds as its `AudioRoute`, R168); `Agent::switch(&mut self)` moves `Open` to `Switching` and refuses with `Error::Closed` when the state is `Closing` or `Closed`, otherwise aborts the pump at an await, awaits it, and takes the session through `Arc::get_mut`, keeping the confirmation state; every return after the abort leaves a pump running on the old or new session, or an agent that has yielded `Closed` (`switch.rs:34-44`); on `SpeechSessionClosed` the pump moves `Open` to `Closing` by compare-and-swap, then spawns the close and keeps receiving, never awaiting it, so the egress it drains cannot block the stop; dropping an unclosed `Agent` cancels its session (`live.rs:942`) and aborts the pump; closing is idempotent, whichever of the application and the model closes first; once closing has started, every newly held confirmation is denied; the `SessionDriver` that `LiveSession::open` and `switch` return (`live.rs:1241`, `:1262`; `switch.rs:83`, `:130-133`) is spawned by the agent at open and after each successful switch, its `JoinHandle` kept in `Inner` and awaited after the session ends on close and by `switch`, and the first of a current-epoch `RunFailed` or `SpeechSessionFailed`, the driver ending (`Ok` or `Err`), `SessionClosed` and `receive` returning `None` closes the agent through the same compare-and-swap, `Closed` yielded exactly once and the `Sender` dropped, a failure or driver `Err` yielding one `Event::Error(Error::Layer)` (R158, R169, R170); each run is an epoch, raised by a successful switch, and an event's epoch is known by its place in the stream: the switch records the old run's drained events and then its run end before the new run's (`switch.rs:104-115`, `live.rs:250-290`), so the pump started after a switch drops every `SpeechStarted`, close, failure and run-end event up to the old run's `RunCompleted` and maps its data events (R153, R165); the agent-level settings (`auto_interrupt`, the event channel and its `Sender`, the sink, the confirmations, the reply tracking) persist across a switch, while the model and session configuration come from the new recipe merged as `open` merges them, with the agent's `auto_interrupt` written in (R156, R157); `auto_interrupt` is an agent setting that survives every switch and controls barge-in on both topologies: a native one through `SpeechStarted`, a cascade through the sink's `TurnOpened`, and off means a `TurnOpened` cuts nothing (R171, R181); `LiveSession::interrupt` records `SessionInterrupted` after its `Cancel` is on every ingress, so input sent after a reader sees it lands behind the `Cancel` (R178) | §3.2, §8 |
| D20 | each duplex provider crate exports `default_session_config()` (`inference-openai`'s `duplex` and `live_duplex`, `inference-aws`'s `duplex`), which the registry descriptor uses; the agent builder's `session_config(SessionConfig)` overrides it whole, the voice override then applied on top | §4.4 |
| D21 | `native_voice` wires the `DuplexNode`'s `tool_call` and `tool_result` ports through the runtime's `ToolAuthority` and `ToolExecutorNode`, so a model's tool call runs the agent's tools and is answered by its call id | §3.3 |
| D22 | the pump sends into a `tokio::sync::broadcast` channel of capacity 1024; `Agent` is not a `Stream`: `Agent::events(&self) -> Events` wraps `tokio_stream::wrappers::BroadcastStream`, the first call taking the receiver made at open, so it yields the buffered events even after the end, and a later call subscribing from that point, ending at once after the end; every `Events` ends after `Closed`, because the pump drops the `Sender` when the session ends; a subscriber that falls behind gets `Event::Lagged(n)`, never a stalled session; audio goes to the sink while a device run has one attached, otherwise onto the channel as `Event::Audio`, and with no sink attached the caller owns playback and cutting, `Event::Interrupted` telling it when to cut (R182); a native recipe exposes one egress, the duplex node's `events` port, so the agent yields events in the node's emission order (a second egress would be drained in index order, `live.rs:976-993`); `Interrupted` is mapped from `SessionInterrupted`, recorded by `agent.interrupt()` or, with the session's `auto_interrupt` on, by the `interrupt()` the pump spawns at a barge-in (`SpeechStarted` while a reply is in progress, from its `GenerationStarted` to its `GenerationCompleted`, or while reply audio is pending at the sink); a barge-in cuts the speaker at once and drops the cut generation's later frames, a frame belonging to the generation of the last `GenerationStarted` before it on the one egress; the cut, a barge-in's or `agent.interrupt()`'s, ends the tracked reply, so a `SpeechStarted` with no reply in progress yields no `Interrupted` (R154, R155); a cascade's events come from several egresses and its speech-to-text node sends a transcript downstream before its exposed egress (`crates/inference-testkit/src/stt/node.rs:443-448`), so a cascade promises no order between `Heard` and `Said`, and its speaker sink is `AcknowledgingSink::over(run_id, RoutedPlayout)` with the cascade's turns, playing through the agent's audio route, the route native audio takes: to the attached device sink during a device run, otherwise onto the channel as `Event::Audio` (R161, R167, R168); a cascade reports no `SpeechStarted`, and its barge-in is the sink's: a `TurnOpened` cuts queued and in-flight frames, calls the route's `cut` and `interrupted` (one `Event::Interrupted`) and counts the interruption, as `AcknowledgingSink::with_turns` does (R181); with `auto_interrupt` off neither topology cuts anything; a failed response (`SpeechResponseFailed`) yields `Event::Error`, never `Interrupted`; `Agent::closed()` resolves once the pump has dropped the `Sender`; `Event` has the twelve variants of the one list in design §3.2; `Event` is `Clone`, its `Error` holding `Arc<inference::Error>` | §3.2, §8 |
| D23 | `Agent::session() -> &LiveSession<Payload>` and `Agent::pipeline() -> &PlannedPipeline`, the escape hatches below the handle | §3.2, §3.5 |
| D24 | a tool with `requires_confirmation` is held by the `ToolAuthority` until `Agent::confirm(call_id)` or `Agent::reject(call_id)` answers it (the authority handle's `confirm` and `deny`, each returning `bool`); the agent yields `Event::ConfirmationRequested` once the call is held, after that call's `Event::ToolCalled` (mapped from `SessionEvent::ToolCallProposed`), and `close` denies every held call first | §3.2, §3.3 |
| D25 | the role is in the type: `Binding::stt`, `llm`, `tts` and `speech` return `Bound<role::Stt>` and the rest, which the agent builder's `stt`, `llm`, `tts` and `speech` take; `Binding::named(Role, ..)` returns the runtime-roled `Binding`, which only `Stack::bind(impl Into<Binding>)` takes | §4.2 |
| D26 | resolving a stack does no I/O: the `aws` registration binds `NovaSonicSpeech::deferred(model_id)`, whose connector loads the AWS configuration when a session opens (`adapters/inference-aws/src/duplex.rs:138-147`, `:231-237`) | §4.4 |
| D27 | every exposure of the five recipes buffers `inference::recipe::EXPOSURE_CAPACITY` (64) events under `OverloadPolicy::Pause`; `Recipe::exposure_capacity(n)` sets it per recipe, a latency against buffering trade-off: a smaller value bounds how far the application falls behind before the model's output pauses and how much is queued behind an interrupt, at the cost of more pauses for a bursty reader | §3.3 |
| D28 | `Recipe::declare_into(&self, declaration: &mut Declaration, catalog: &dyn Catalog, profile_id: ProfileId, adapters: &[(Role, AdapterId)], requires: &[(Role, &[Capability])]) -> Result<PipelineId, Error>` declares a recipe into a caller-owned declaration built over the caller's catalog and profile (`crates/inference-pipeline/src/builder.rs:554`), so the profile's admitted localities and the catalog reach planning, which the caller runs with `declaration.plan(validated, catalog)`; it binds each role's node to that role's adapter and replaces the requirements of each role named in `requires`; a caller reads the recipe's node and port ids through `nodes()` and `ports()` filtered by `pipeline_id()`, because a shared declaration holds every pipeline declared in it; `local_voice_cascade::declare_requiring` keeps its signature and builds through it (R191). The argument types come from the module re-exports `inference::pipeline::{Catalog, Declaration, PipelineId}`, `inference::core::policy::ProfileId` and `inference::core::model::{AdapterId, Capability}` (story:sdk-crate) and `inference::Role` (story:sdk-stack). It checks the profile and every adapter id against the catalog before declaring anything, so a refusal leaves the declaration unchanged and is `Error::Layer`, its message naming the missing id and its `source()` the pipeline's `ProfileNotFound` or `AdapterNotFound` (§9; R195, R196). The instantiation passes a `Stack` as the catalog, with `Stack::profile_id()` and `Stack::adapter_ids() -> Vec<(Role, AdapterId)>` (story:sdk-stack); `Recipe::declaration()` is the stack-free form, the recipe's unbound topology under a built-in `offline_strict` profile, for inspection and tests (R197). It binds only the roles the recipe has nodes for and ignores other pairs; a needed role with no pair is refused in the same up-front check as `Error::Layer` naming the role, declaration unchanged, while the instantiation checks roles first and returns `Error::RoleUnbound` (R202). A recipe's roles are those of its role-bound nodes: the built-ins' model nodes, a node `with_node` replaces keeping its role, and any node `Recipe::role(node, Role)` names; a node without a role needs no binding (R207) | §3.3 |
| D29 | `Error::kind(&self) -> ErrorKind`, where `inference::ErrorKind` is `#[non_exhaustive]` with one value per `Error` variant, named as it; `Error::Layer { message: String, source: Option<Box<dyn std::error::Error + Send + Sync>> }`, whose `source()` returns `source` (story:sdk-crate, R199); `ErrorKind` is in `inference::prelude` (R206); `Error::ProfileDenies { role: String, adapter, locality, profile, source: LocalityDenied }` names the role, the adapter and its locality, then the fix `profile = "hybrid_opt_in"` with every source that sets it, built by the instantiation from planning's `LocalityDenied` and the denied node's role; `role` is a `String` because `Role` lives in story:sdk-stack (R203, R212) | §9 |
| D30 | a stack with no `profile` key declares `offline_strict` (`Egress::Denied`, admitting `SameProcess` and `LocalWorker`), so a hosted adapter needs `profile = "hybrid_opt_in"` named and is otherwise refused at planning with `ProfileDenies` (story:sdk-stack, R201); `profile` has the sources and order of a role key, `Stack::profile(ProfileKind)`, `INFERENCE_PROFILE`, then the three files, recorded by `Stack::profile_source() -> Option<BindingSource>` (R204) | §4.1, §4.3 |
| D31 | an application recipe: `Recipe::custom(name: &str, mode: InteractionMode, declare: impl Fn(&mut inference::graph::Builder<'_, '_>) -> Result<(), Error> + Send + Sync + 'static) -> Recipe`; `Recipe::role(self, node_name: &str, role: Role) -> Recipe` makes a node role-bound (R207); `Recipe::register(self) -> Result<(), Error>` adds it to a process-wide table under its name, refusing a name already held (a built-in's or an earlier registration's) with `Error::Layer` naming it; `Recipe::named(name: &str) -> Option<Recipe>` returns the built-in or registered recipe of that name; `Recipe` is `Clone`, its declare function in an `Arc`. The plan named no registration or lookup call before; `register` and `named` are chosen here (story:sdk-recipes, R209). The table is process-wide, so `named` needs no handle, and has no removal; each test registers under a name of its own and asserts the taken-name refusal inside the same `#[test]` as the first registration (R214). This is an allowed exception to D17's rule that tests inject their inputs and touch no process-wide state: registration is append-only and keyed by name, so registrations under distinct names cannot interfere, which an environment variable read by every resolve could. ESS `inference.sdk.RegisterRecipe`, outcomes `registered` and `name-taken` (R216) | §3.3 |
| D32 | an application adapter: `Registry::register(descriptor: AdapterDescriptor) -> Result<(), Error>`, the descriptor built by `AdapterDescriptor::new(name: &str, locality: Locality)`, `.role(role: Role, construct: impl Fn(&BTreeMap<String, String>) -> Result<Binding, Error> + Send + Sync + 'static)` once per role it serves, `.feature(&'static str)` and, for `speech`, `.session_config(SessionConfig)`; the table is keyed by adapter name alone, one descriptor per name listing every role it serves, process-wide and append-only with no removal, as D31's recipe table and under the same D17 exception; a name already held, a built-in's or an earlier registration's, is refused with `Error::Layer` naming it, asserted in the same `#[test]` as the first registration (story:sdk-stack, R217); the built-in names are reserved whatever the features, so registering one is refused with `Error::Layer` naming it even when its feature is off (R222); at resolve, `Error::Layer` refuses a constructor's binding of another role and a returned `Binding::named(..)`, so a registration cannot resolve to another name (R219) | §4.4 |

## Open questions

Q1 to Q5 of `docs/design/sdk.md` §12, each with the default the draft takes. Q5 (audio tokens have

## Specification

`ess/domains/sdk.yaml`: `Stack`, `StackBinding`, `Recipe`, `Instantiation`. The resolve,
instantiate and register-recipe commands are UNMAPPED there and belong to story:sdk-stack and story:sdk-recipes, whose
conformance scenarios are `inference.sdk.ResolveStack/outcome/<outcome>`,
`inference.sdk.InstantiateRecipe/outcome/<outcome>` and `inference.sdk.RegisterRecipe/outcome/<outcome>`.
